Con el plugin **Events Whitelist** instalado, la whitelist se sincroniza sola: cuando alguien se
registra (o se le quita) en Discord, entra o sale de la whitelist del servidor al instante, sin
que tengas que exportar ni tocar nada.

## Compatibilidad

| | |
|---|---|
| Versiones de Minecraft | **1.16.5 → última** (el mismo JAR, sin recompilar) |
| Servidores | Spigot, Paper, Purpur, Pufferfish y forks |
| Java | 8 o superior (8, 11, 17, 21, 25…) |
| Redes (BungeeCord / Velocity) | No contemplado: está pensado para un solo servidor |

## 1. Consigue tu clave de conexión

En Discord, con permisos de staff:

```
/whitelist server-link create nombre:"Mi servidor"
```

- `nombre` es solo para identificarlo tú en `/whitelist server-link list`.
- Si quieres que la clave sincronice **una sola** whitelist (y no todas las del servidor de
  Discord), añade `whitelist:` y elige cuál.

<Warning>
  **La clave se muestra una única vez**, en un mensaje privado. Cópiala en ese momento: el bot no
  puede volver a enseñártela. Si la pierdes, genera una nueva con `server-link create` y revoca
  la antigua con `server-link revoke`.
</Warning>

## 2. Instala el plugin

<Steps>
  <Step title="Copia el .jar">
    Deja `EventsWhitelist.jar` en la carpeta `plugins/` de tu servidor y arráncalo. Se crean
    `config.yml` y la carpeta `whitelists/` con dos listas de ejemplo (`publica` y `staff`).
  </Step>
  <Step title="Activa la whitelist">
    ```
    /wl on
    ```
  </Step>
  <Step title="Vincula tu Discord">
    ```
    /ewl server-link setup TU_CLAVE
    ```
    Solo la clave: la dirección de la API ya viene en `config.yml`. El plugin se recarga y
    prueba la conexión.
  </Step>
  <Step title="Comprueba el estado">
    ```
    /ewl server-link status
    ```
    Debe decir WebSocket **conectado** y listar las whitelists sincronizadas.
  </Step>
</Steps>

<Note>
  **Actualizar desde 1.3.x.** La clave se conserva y el servidor sigue vinculado. Los nicks
  añadidos a mano en modo `custom` (`custom-whitelist.yml`) no se migran: vuelve a añadirlos con
  `/wl add`.
</Note>

## 3. Varias whitelists

Cada whitelist es un archivo en `plugins/EventsWhitelist/whitelists/<id>.json`. Puedes tener
varias activas a la vez (staff, pública, evento…): un jugador entra si está en **cualquiera** de
las activas.

| | Locales | De Discord |
|---|---|---|
| Se crean con | `/wl create` | Automáticamente al vincular, o `/ewl server-link import` |
| Añadir y quitar gente | `/wl add` / `/wl remove` | Desde Discord |
| Activar, desactivar, renombrar | Sí | Sí |

Para editar en el juego una lista de Discord, haz una copia local con `/wl clone`.

### Modo de fusión (`sync.mode`)

| Modo | Qué hace |
|---|---|
| `additive` (por defecto) | Solo añade y quita a los jugadores que gestiona el plugin. Lo añadido con `/minecraft:whitelist add` **no se toca**. |
| `mirror` | La whitelist del servidor refleja **exactamente** las listas activas. Borra todo lo demás. |

## `/wl`: whitelists

Sustituye al `/whitelist` de vanilla (el original sigue en `/minecraft:whitelist`).

| Comando | Qué hace |
|---|---|
| `/wl status` | Whitelists, cuáles están activas y cuánta gente tiene cada una |
| `/wl list [whitelist] [página]` | Lista las whitelists o los miembros de una |
| `/wl check <jugador>` | En qué whitelists está y si puede entrar |
| `/wl add <jugador\|selector> [whitelist]` | Añade. Acepta `@a`, `@a[team=Jugador]`, `@p`, `*`… |
| `/wl remove <jugador\|selector> [whitelist]` | Quita de una whitelist, o de todas si no indicas ninguna |
| `/wl create <id> [nombre]` | Crea una whitelist |
| `/wl set <whitelist>` | Whitelist por defecto de `/wl add` |
| `/wl clone <origen> <id-nuevo>` | Copia local y editable |
| `/wl enable\|disable <whitelist>` | Activa o desactiva una whitelist |
| `/wl lock\|unlock <whitelist\|all>` | Cierra a altas nuevas; quitar gente sigue funcionando |
| `/wl clear <whitelist> confirm` | Vacía una whitelist |
| `/wl delete <whitelist> confirm` | Borra una whitelist |
| `/wl on` / `/wl off` | Activa o desactiva la whitelist del servidor |

## `/ewl server-link`: vínculo con Discord

| Comando | Qué hace |
|---|---|
| `/ewl server-link setup <clave>` | Vincula el servidor |
| `/ewl server-link status` | Estado del vínculo y listas sincronizadas |
| `/ewl server-link test` | Prueba la conexión |
| `/ewl server-link sync` | Sincroniza ahora |
| `/ewl server-link list` | Whitelists de Discord que ve la clave |
| `/ewl server-link import <id\|all>` | Trae una whitelist de Discord |
| `/ewl server-link filter <id\|none>` | Sincroniza solo una whitelist, o todas |
| `/ewl server-link autosync <on\|off>` | Sincronización automática |
| `/ewl server-link key <clave>` | Cambia la clave |
| `/ewl server-link unlink confirm` | Desvincula (las listas locales se quedan) |

Otros: `/ewl status`, `/ewl reload`, `/ewl update [check\|download]`.

<Note>
  Permisos: `eventswhitelist.admin` para todo, `eventswhitelist.manage` para editar listas y
  `eventswhitelist.view` para verlas. Por defecto, solo operadores.
</Note>

## Qué pasa si el servidor pierde la conexión

El plugin reconecta solo (hasta 60 s entre intentos) y al reconectar sincroniza todo lo que se
perdió.

## `config.yml` del vínculo

```yaml
api:
  base-url: "https://whitelist-api.eventsmc.xyz"   # vacío = la oficial
  api-key: ""                 # /ewl server-link setup <clave>
  whitelist-id: ""            # vacío = todas las que vea la clave
  auto-import: true
  auto-sync: true
```

La clave viaja siempre por HTTPS/WSS en la cabecera `Authorization`, nunca en la URL.

## Desconectar un servidor

```
/whitelist server-link list      → mira el id
/whitelist server-link revoke id:<id>
```

La clave deja de funcionar al instante.

## Eventos en tiempo real por webhook

Además del WebSocket que usa el plugin, puedes recibir los mismos eventos (alta/baja de nicks) en
tu propia integración:

```
/whitelist server-link webhook id:<id-del-vínculo> url:https://tu-servidor.com/webhook
```

Deja `url` vacío para quitarlo. Ver [API](/whitelist/api) para el formato de los eventos.
